How SmartSwap decides

every 200 ms
  1. 1Feel it

    A tiny canary task wakes every 40 ms and times its scheduling delay, compute, memory copy and disk read.

  2. 2Name it

    Whichever part slowed down tells the cause: waiting for a core means CPU, a slow copy means memory bandwidth, a slow read means storage.

  3. 3Fix it cheaply

    First lower background priority. Only if that is not enough, cap background CPU and tune the cap up and down.

  4. 4Prove it

    Read every change back from Windows, check the stall actually dropped, and undo anything that did not help.

Run a controlled experiment

SmartSwap starts its own bounded background workload and a foreground probe, applies one policy to the background only, and measures the probe's tail latency and what the policy cost the background. Every action is verified by reading it back from Windows, then reverted.

What the study shows

A randomised block study: every workload × policy pair runs once per block, in random order. Results are medians of per-block ratios with 95% bootstrap intervals and exact Wilcoxon tests, Holm-corrected across every comparison.

Safety guarantees

  • Acts only on background processes SmartSwap itself started.
  • Never raises a priority; never needs administrator rights.
  • Every action and every revert is read back from Windows.
  • No page-file, standby-list, service, or system-setting changes.
